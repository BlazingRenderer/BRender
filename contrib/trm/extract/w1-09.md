## Notes

- Transcribed 43 entries.
- The pages in this range are almost entirely *type* documentation (br_filesystem
  members, br_font, br_fraction, br_fvector2/3/4), which I have not transcribed.
  Only the function reference entries are above.
- Two entry formats occur here:
  - `BrFilesystemSet` uses the normal boxed `Description:/Declaration:/Arguments:/Result:`
    layout.
  - The `BrFixed*` and conversion entries use the compact inline layout — the
    declaration line followed by an indented one-line description. There is no
    `Description:`/`Arguments:`/`Result:` label, so I have put the one-line text
    under `description:`. There are no argument descriptions and no separate
    return descriptions for these.
- The `BrFixed*` block is a single continuous list running pages 132–134; three
  entries (`BrFixedMac4`, `BrFixedMac3Div`) have their declaration split across a
  page break and are marked with a page range.
- Possible manual inconsistency: `BrFixedFMac4`'s printed declaration types the
  parameters `a b c d e f g h` as `br_fixed_ls`, yet its description says
  "a, c, e, & g are fractions" and `BrFixedFMac2`/`BrFixedFMac3` type their
  fraction arguments as `br_fixed_lsf`. Transcribed as printed.
- `BrIntToFixed`, `BrFloatToFixed`, `BrFixedToInt` and `BrFixedToFloat` are
  printed without a return type and in the macro style (parenthesised name, no
  declared return), so they appear to be macros rather than functions. I have
  transcribed them because they are Br-prefixed and documented alongside the
  real functions; they should be treated as macro entries.
- All-uppercase macro entries in this range are NOT transcribed (out of scope for
  function reference entries): `BR_ONE_LS`, `BR_ONE_LSF`, `BR_ONE_LU`,
  `BR_ONE_LUF`, `BR_ONE_SS`, `BR_ONE_SSF`, `BR_ONE_SU`, `BR_ONE_SUF` (p135);
  `BR_FMAC2`, `BR_FMAC3`, `BR_FMAC4`, `BR_FRACTION` (p141); `BR_SCALAR_EPSILON`
  (p142); `BR_FVECTOR2`, `BR_FVECTOR3`, `BR_FVECTOR4` (p143–145).
- No illegible glyphs; no `[?]` markers were needed.
